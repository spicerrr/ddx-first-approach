# Первый подход

**Необязательное интерактивное знакомство с тренажёрным залом внутри DDX Fitness App — продуктовая гипотеза и самостоятельный аналитический кейс.**

У DDX уже есть Smart Start и ознакомительная тренировка. Вопрос проекта — существует ли среди новых участников проблема **обнаружения и использования** этих услуг и может ли короткая интерактивная практика помочь лучше обычной информационной карточки. Данных, подтверждающих такую проблему, у автора нет: проект не представляет её как установленный факт.

## Коротко о сценарии

1. Участник добровольно запускает игру — это не обязательная часть подписки.
2. Возвращает три пары гантелей в подписанные зоны, размещает виртуальные диски симметрично, проходит шесть проверок обращения со скамьёй, раскладывает восемь предметов по зонам.
3. Получает объяснение на ошибочные действия и может вернуться к прогрессу.
4. Видит краткие правила и переход к **существующим** программам Smart Start / ознакомительной тренировки. Прямой переход доступен и до завершения игры — нельзя превращать образовательную механику в барьер для записи. Игра не создаёт запись и не выдаёт допуска к работе на оборудовании.

## Запуск прототипа

```bash
python3 -m http.server 8080
# открыть http://localhost:8080/first-set/demo/
```

Запускайте из корня репозитория. Backend и доступ к DDX не требуются; локальный прогресс записывается в `localStorage`. Здесь нет работающих серверной авторизации, OpenAPI-интерфейса, брокера или интеграций — их **проектные** модели находятся в разделе SA.

## Статус и границы

Это самостоятельная доработка учебной концепции НИУ ВШЭ, не заказ, не официальная инициатива и не реконструкция закрытой архитектуры DDX Fitness/DDX TECH. Материалы DDX использованы как публичный продуктовый контекст; неизвестные механизмы приложения отмечены отдельно. Следующий шаг перед коммерческой разработкой — аудит текущего онбординга и валидация проблемы.
