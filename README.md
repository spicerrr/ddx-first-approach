# «Смена» — SA-кейс игровой фичи для приложения DDX Fitness

Проектная спецификация мобильной мини-игры **внутри существующего приложения DDX Fitness**. Игрок проходит три станции в роли дежурного тренера: возвращает гантели на стойку, собирает заданный вес штанги, показывает игровому посетителю регулировку скамьи Foreman на вращаемой 3D-модели и сортирует инвентарь. После результата приложение предлагает перейти к записи на Smart Start.

> Это портфельный концепт, а не заказ DDX и не описание внутренних систем компании. Публично подтверждены наличие приложения, раздел видеоинструкций к тренажёрам в профиле и запись на Smart Start. Наличие именно FW-702 в клубах DDX, мобильный стек, внутренние API и аналитические контракты не подтверждены; ниже — проектные предложения.

## Продуктовая декомпозиция

| Уровень | Состав | Граница |
| --- | --- | --- |
| Существующий продукт | аккаунт, авторизация, клубный контекст, каталог видеоинструкций, запись на Smart Start | использует уже имеющиеся механизмы, их контракты неизвестны |
| Новая фича «Смена» | карточка в инструкциях, игровые экраны, вращаемый гайд, результат, возобновление | модуль приложения, единая с ним авторизация |
| Новый доменный контур | конфигурации сценариев, сессии, ответы, состояние, история, идемпотентность | предлагаемый игровой API и хранилище |
| Интеграция | переход в каталог/расписание Smart Start и атрибуция перехода | запись и её правила остаются в текущем контуре DDX |

**Цель MVP:** проверить, помогает ли короткий игровой сценарий новому участнику освоиться с пространством клуба и чаще перейти к записи на Smart Start. Игра не подтверждает навыки тренера, не назначает нагрузку и не заменяет инструктаж.

**В составе MVP:** один опубликованный набор станций, сохранение прогресса на сервере, повторное прохождение после завершения/отказа/истечения, ссылка на Smart Start, продуктовые события. **Вне MVP:** награды, баллы, скидки, публичный рейтинг, физическая уборка или обращение реального посетителя через игру, управление бронированиями Smart Start.

Сценарии оплаты и продления подписки, заморозки, прохода через турникет и бронирования занятий принадлежат другим процессам продукта. Здесь специфицирована граница с существующим Smart Start. Платёжный шлюз, вебхуки и правила рекуррентных списаний требуют самостоятельного кейса с отдельными состояниями и данными; включение их в игру исказило бы её предметную область.

## Проверка согласованности

```bash
python3 scripts/check_case.py
```

Скрипт проверяет ссылки OpenAPI и AsyncAPI, набор состояний, трассировку требований к критериям, состав игрового сценария и расчёт штанги. Прототип в HTML запускается локально в браузере; его модель схематична, точный GLB ещё не изготовлен. Проверка не доказывает совместимость с приватными сервисами DDX.

## Основание для продуктового контекста

- [DDX Fitness — Smart Start](https://www.ddxfitness.ru/smart-start/): занятия доступны на всех тарифах, запись ведёт в приложение, тренер показывает работу с оборудованием.
- [DDX Fitness — описание программы](https://www.ddxfitness.ru/blog/training/smart-start/): запись на сайте или через мобильное приложение.
- [DDX Fitness — первая тренировка](https://www.ddxfitness.ru/blog/training/pervaya-trenerovka-v-fitness-klube/): контекст адаптации новичка и правила зала.
