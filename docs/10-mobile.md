# 10. Мобильный клиент: сеть, версии и тактильный отклик

## Принцип хранения

Подтверждённое состояние сессии хранится на сервере. На устройстве сохраняются последний полученный снимок и **черновик текущей расстановки**, который ещё не отправлен по кнопке «Проверить». Черновик не является успешным прохождением станции. Локальная запись содержит `ownerId`, `sessionId`, `scenarioVersion`, `scenarioSchemaVersion`, `serverVersion`, `stage`, размещения предметов и время сохранения. При выходе из аккаунта или смене пользователя запись удаляется; чужому аккаунту она не показывается.

### Плавающий сигнал и офлайн

| Условие | Поведение клиента |
| --- | --- |
| Приложение открыто без сети, есть снимок той же учётной записи | показать этап и локальный черновик с отметкой «Нет сети»; предметы можно переставлять; «Проверить» недоступно до синхронизации |
| Нет сети и нет пригодного снимка | показать состояние подключения и повтор загрузки; не выдавать новый сценарий локально |
| Сеть пропала **до** отправки команды | сохранить черновик, не создавать серверную попытку; после восстановления сначала GET, сверить ID/версию/этап, затем предложить проверить |
| Сеть пропала **после** отправки, ответ неизвестен | сохранить метод, путь, тело и ключ команды; при восстановлении повторить именно её с тем же ключом, затем GET; новую команду пока не отправлять |
| GET показывает ту же сессию/версию/этап | восстановить черновик и разрешить проверку |
| GET показывает другой этап, истечение, отказ или изменение версии с другого устройства | отобразить серверный этап, не отправлять старый черновик; при необходимости сообщить, что прогресс обновился |
| Приложение ушло в фон или было закрыто | локальный черновик переживает перезапуск; серверный статус не меняется из-за фонового режима |

Локальный снимок хранится в защищённом хранилище приложения; токен авторизации, имя и сведения о других пользователях в черновик не попадают. Срок хранения черновика не дольше срока сессии и очищается после COMPLETED/ABANDONED/EXPIRED. Детали защиты на устройстве согласуются с мобильной платформой DDX.

## Совместимость версий

Клиент посылает `X-Game-Schema-Version: 2`. Сервер возвращает `scenarioSchemaVersion: 2` вместе с сессией и не выдаёт неподдерживаемую схему задания. При входе сервер сначала ищет активную сессию: совместимый старый клиент продолжает её по прежнему снимку. Если её нет, а опубликованный сценарий требует более новой схемы, вход/запуск возвращает 426 `CLIENT_UPGRADE_REQUIRED` и экран предлагает обновить приложение. Начатая сессия не меняется при публикации нового сценария. Версия схемы описывает формат данных и действий, `scenarioVersion` — содержимое станций. Выпуск игрового API под выключенным флагом предшествует включению карточки в приложении.

## Переход в Smart Start

После COMPLETED приложение вызывает свой навигатор с целью `SMART_START_CATALOG` и источником `shift_result`; точный адрес или схема ссылки DDX здесь неизвестны. Если целевой экран требует авторизации, сначала происходит штатное восстановление входа. Если маршрут не открылся, игра остаётся в результате и позволяет повторить переход. Возврат из Smart Start не меняет COMPLETED. Для внешней ссылки из будущего уведомления предлагается цель `SHIFT_ENTRY`: клиент проверяет вход и серверное состояние, а не доверяет `sessionId` в ссылке.

## Уведомления

В MVP уведомления **не отправляются**: у сессии нет таймера, требующего немедленного действия, а событие помощи появляется только внутри игры. Возможное расширение после проверки пользы: одно напоминание о незавершённой сессии не раньше чем через 24 часа при наличии согласия на уведомления, отсутствии COMPLETED/ABANDONED/EXPIRED и не чаще одного на сессию. Перед отправкой снова проверяются статус и настройки уведомлений; открытие ведёт в `SHIFT_ENTRY`. Для этого потребуется отдельный контракт с действующей системой уведомлений DDX. Уведомление не служит источником состояния игры.

## Рендер модели и кэш контента

3D-гайд получает версию GLB, SHA-256 и размер из манифеста. Ассет загружается вне транзакции игрового шага, проверяется по хешу, кэшируется по `guideId+guideVersion` и удаляется при смене пользователя/версии или вытеснении. При повреждении, отсутствии сети без кэша, нехватке памяти либо сбое рендера клиент показывает видео/ключевые кадры и текст с теми же шестью кнопками действий. Поворот, просмотр и повтор клипа — локальные действия; клиент отправляет команду подтверждения только при доступной сети и после сверки версии сессии. Режим снижения движения заменяет анимацию ключевыми положениями. Конкретный 3D-движок, пределы памяти и FPS уточняются по реальному мобильному стеку DDX.

## Тактильный отклик на блины для iPhone

При захвате блина — **один короткий импульс**, интенсивность которого растёт с массой. При фиксации в допустимой точке грифа — короткое одинаковое подтверждение, мягче самого сильного сигнала захвата. Оно сообщает о действии интерфейса; правильность общего веса определяется по кнопке «Проверить». Перемещение пальца не генерирует непрерывных импульсов. Предустановленные блины 20 и 5 кг не перетаскиваются и отклика не дают.

| Масса доступного блина | Предлагаемая интенсивность импульса захвата Core Haptics от 0 до 1 | Ощущение для теста |
| --- | ---: | --- |
| 1,25 кг | 0,25 | лёгкое касание |
| 2,5 кг | 0,40 | заметный лёгкий импульс |
| 5 кг | 0,60 | средний импульс |
| 10 кг | 0,80 | более плотный импульс |

Интенсивности — **параметры прототипа**, их проверяют на реальных iPhone; устройство и настройки системы могут изменить фактическое ощущение. Использовать `Core Haptics` с проверкой `supportsHaptics`; при недоступности пользователь получает обычное визуальное подтверждение. Ошибка размещения обозначается текстом/цветом и отдельным системным сигналом ошибки только после «Проверить», чтобы сильный блин не путался с ошибкой. Тактильный отклик можно отключить в игре; системные ограничения имеют приоритет. Базовое действие доступно через выбор блина и стороны без перетаскивания; вес всегда подписан текстом.

**Проверка ощущения:** на устройстве с поддержкой тактильного отклика пользователи различают крайние уровни 1,25 и 10 кг без подсказки; после нескольких сборок нет жалоб на навязчивые повторные импульсы. Числовые уровни меняют по результатам проверки, не по произвольной формуле «килограммы → мощность».

Документация Apple: [Core Haptics](https://developer.apple.com/documentation/corehaptics), [параметр интенсивности](https://developer.apple.com/documentation/corehaptics/chhapticevent/parameterid/hapticintensity), [проверка поддержки](https://developer.apple.com/documentation/corehaptics/chhapticdevicecapability/supportshaptics), [рекомендации по тактильному отклику](https://developer.apple.com/design/human-interface-guidelines/playing-haptics).
