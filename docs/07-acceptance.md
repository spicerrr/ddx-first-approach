# 07. Acceptance criteria

Ниже проверки пользовательской фичи и серверного контракта. Для автоматизации используются опубликованный сценарий `scenarioVersion=2.0`, тестовый пользователь и управляемые часы.

| ID | Given / When / Then |
| --- | --- |
| AC-01 | **Given** авторизованный участник с активным членством и включённым флагом; **when** открыт вход; **then** GET /v1/shift возвращает `available:true`, а при активной сессии — её ID для «Продолжить». При выключенном флаге старт недоступен. |
| AC-02 | **Given** у участника нет незавершённой сессии; **when** POST /sessions с новым ключом; **then** 201, `ACTIVE/DUMBBELLS v1`, снимок сценария, время истечения и одно событие старта. |
| AC-03 | **Given** DUMBBELLS; **when** шесть уникальных гантелей разложены по трём секциям попарно и по весу; **then** `accepted:true`, BARBELL. Неправильная пара даёт `accepted:false/WRONG_PAIR`, остаётся DUMBBELLS. |
| AC-04 | **Given** BARBELL с грифом 20 кг и предзагрузкой 20+5 кг с каждой стороны; **when** добавлены 2,5+1,25 кг слева и справа; **then** масса 77,5 кг, `accepted:true`, PAUSED_HELP. При 2,5+1,25 только слева — `ASYMMETRIC`; при симметричном неверном весе — `WRONG_TOTAL`. |
| AC-05 | **Given** PAUSED_HELP; **when** клиент отправляет ответ EQUIPMENT; **then** 409 INVALID_TRANSITION и стадия остаётся HELP. |
| AC-06 | **Given** PAUSED_HELP с `nextStepIndex=0`; **when** отправлен `SEAT_LEVER` или неверный `targetId`; **then** `accepted:false/WRONG_ORDER` либо `WRONG_CONTROL`, индекс остаётся 0, версия растёт. Только корректные шесть шагов открывают EQUIPMENT. |
| AC-07 | **Given** EQUIPMENT; **when** все 8 уникальных объектов (2 каждого типа) распределены в соответствующие четыре зоны; **then** COMPLETED/RESULT. Один предмет в неверной зоне даёт WRONG_ZONE, результат не открывается. |
| AC-08 | **Given** сессия PAUSED_HELP или ACTIVE/EQUIPMENT; **when** приложение закрыто и пользователь зашёл с другого устройства; **then** GET возвращает ту же версию, снимок и текущий этап без создания новой сессии. |
| AC-09 | **Given** COMPLETED; **when** пользователь запускает игру снова; **then** создаётся другой sessionId, DUMBBELLS v1, а завершённая сессия остаётся в истории. |
| AC-10 | **Given** ACTIVE; **when** подтверждён ABANDON; **then** ABANDONED/NONE. Команда этапа к старой сессии возвращает INVALID_TRANSITION; новый START разрешён. |
| AC-11 | **Given** ACTIVE; **when** другой ключ START отправлен параллельно; **then** ровно одна новая сессия, второй запрос получает ACTIVE_SESSION_EXISTS и её ID. |
| AC-12 | **Given** COMPLETED; **when** нажата кнопка Smart Start; **then** навигатор открывает действующий экран записи с `source=shift_result`, событие клика содержит sessionId; запись подтверждается только действующим модулем Smart Start. |
| AC-13 | **Given** успешная команда и потерянный HTTP-ответ; **when** тот же ключ, метод, путь и тело отправлены снова; **then** тот же статус/тело, прежняя версия, одна попытка и один набор исходящих событий. |
| AC-14 | **Given** две разные команды с одной ожидаемой версией; **when** они приходят одновременно; **then** одна обрабатывается, другая получает VERSION_CONFLICT и ничего не меняет. Тот же ключ с другим телом получает IDEMPOTENCY_KEY_REUSED. |
| AC-15 | **Given** участник B знает ID сессии участника A; **when** B читает или изменяет её; **then** 404, данные A не раскрываются и не меняются. |
| AC-16 | **Given** успешная команда; **when** публикация аналитики временно недоступна; **then** игровой ответ остаётся успешным, таблица исходящих событий сохраняет запись, повторная доставка не даёт дубль по eventId. |
| AC-17 | **Given** POST завершился таймаутом на клиенте; **when** клиент повторяет запрос с тем же ключом, затем делает GET; **then** показано состояние сервера без двойной попытки или пропуска этапа. |
| AC-18 | **Given** с последней новой команды прошло 7 суток; **when** обработчик или POST проверяет срок; **then** EXPIRED/NONE фиксируется один раз; старый POST получает SESSION_EXPIRED, новый START разрешён. |
| AC-19 | **Given** пользователь на BARBELL разложил блины, но связь пропала до «Проверить»; **when** приложение закрыто и открыто без сети; **then** виден его черновик и отметка сети, перемещение доступно, серверная попытка не создана, «Проверить» недоступно. |
| AC-20 | **Given** связь пропала после POST и ответ неизвестен; **when** сеть вернулась; **then** клиент повторяет тот же метод, путь, тело и ключ, получает исходный ответ, делает GET и не создаёт вторую попытку. |
| AC-21 | **Given** на устройстве сохранён черновик участника A; **when** A вышел и вошёл B; **then** черновик A удалён и не отображается B. |
| AC-22 | **Given** клиент поддерживает схему 1, активной сессии нет, а новый сценарий требует схему 2; **when** он открывает игру; **then** 426 CLIENT_UPGRADE_REQUIRED и предложение обновить приложение. |
| AC-23 | **Given** iPhone поддерживает тактильный отклик и он включён; **when** игрок по очереди захватывает блины 1,25/2,5/5/10 кг; **then** каждый захват даёт один короткий импульс с возрастающей интенсивностью, а фиксация блина на допустимой стороне — одинаковое мягкое подтверждение без утверждения о верности общего веса. При перемещении импульсы не повторяются. При отключении/отсутствии поддержки остаётся визуальный отклик и подпись веса. |
| AC-24 | **Given** завершённая сессия; **when** открыт Smart Start и затем совершен возврат; **then** результат остаётся COMPLETED. Внешняя ссылка SHIFT_ENTRY после восстановления входа читает сессию через GET и не доверяет указанному в ссылке ID без проверки владения. |
| AC-25 | **Given** успешная команда породила несколько событий; **when** отправитель публикует их повторно после сбоя; **then** ключ каждого сообщения равен sessionId, stateVersion соответствует зафиксированной версии, eventSequence последовательна внутри сессии, а получатель учитывает каждый eventId один раз. |
| AC-26 | **Given** участник начал сценарий схемы 1, затем опубликована схема 2; **when** старый клиент открывает свою сессию; **then** он продолжает снимок схемы 1, если она поддерживается; новая сессия со схемой 2 требует обновления клиента. |

| AC-27 | **Given** PAUSED_HELP v3; **when** клиент последовательно подтверждает `BACK_PIN/back_pull_pin`, `BACK_ADJUST/backrest_adjust`, `BACK_LOCK/back_pull_pin`, `SEAT_LEVER/seat_lever`, `SEAT_ADJUST/seat_adjust`, `SEAT_LOCK/seat_lever`; **then** промежуточные ответы сохраняют PAUSED_HELP с индексами 1…5, финальный — ACTIVE/EQUIPMENT v9. Каждая команда записывает попытку и `game_help_step_completed`, финальная также `game_help_resolved`. |
| AC-28 | **Given** модель доступна; **when** игрок поворачивает камеру, запускает/повторяет отдельный клип или открывает текст шага; **then** 3D-геометрия и активная зона видны с нового ракурса, `version` и индекс не меняются до POST /help/act; нажатие на неподходящую зону не считается правильным шагом. |
| AC-29 | **Given** ссылка на FW-702; **when** GET /v1/equipment-guides/{guideId}; **then** манифест содержит точный `equipmentCatalogRef`, версию, SHA-256, размер, клипы, зоны и резервное видео. При несовпадении хеша, отсутствии ассета, нехватке памяти или невозможности 3D-рендера открывается видео/текст, игровой шаг не засчитывается автоматически. |
| AC-30 | **Given** пользователь открыл ту же инструкцию из профиля; **when** он прошёл все клипы вне игры; **then** статус игры не меняется. При возврате в PAUSED_HELP игра загружает серверный `nextStepIndex`; при офлайн-просмотре команда подтверждения ждёт сверки сети и версии. |

### Набор контрольных данных

`DUMBBELLS`: `D8A,D8B→R8`; `D12A,D12B→R12`; `D16A,D16B→R16`. `BARBELL`: `L_2_5,L_1_25` и `R_2_5,R_1_25`; отвлекающие `L_5,R_5,L_10,R_10`. `EQUIPMENT`: `M1,M2→MAT`, `F1,F2→MFR`, `B1,B2→FITBALL`, `C1,C2→BLOCK`. ID из тестового сценария, а не реальные инвентарные номера.
