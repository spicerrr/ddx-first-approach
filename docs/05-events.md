# 05. Продуктовые события и метрики

## Контракт

Общие поля серверного события: `eventId` (UUID), `eventName`, `occurredAt` (UTC), `sessionId`, `stateVersion`, `eventSequence`, `scenarioVersion`, `source=shift`, `payload`. Серверные события идут через таблицу исходящих сообщений по [AsyncAPI](../contracts/asyncapi.yaml). Клиентские события содержат `clientEventId`, `appPlatform` и согласованный с аналитикой обезличенный ID; они не выступают источником подтверждённого прохождения.

| Событие | Источник | Когда | Дополнительные поля |
| --- | --- | --- | --- |
| `game_opened` | клиент | открыт входной экран | entryPoint, flagVariant |
| `game_session_started` | сервер | START принят | sessionId |
| `game_stage_attempted` | сервер | новый ответ на станцию или действие в HELP, включая ошибочный | stage, attemptNumber, accepted, feedbackCode |
| `game_stage_completed` | сервер | верный ответ | stage, attemptsOnStage |
| `game_help_shown` | сервер | S2 перевела в PAUSED_HELP | eventType=ADJUST_BENCH |
| `game_help_step_completed` | сервер | очередной правильный шаг | stepId, stepIndex |
| `game_help_resolved` | сервер | завершён шестой шаг | attemptsOnHelp |
| `game_session_completed` | сервер | S3 завершена | durationSeconds, totalAttempts |
| `game_session_abandoned` / `game_session_expired` | сервер | терминальный переход | lastStage |
| `smart_start_clicked` | клиент | нажата кнопка на результате | sessionId, destination=SMART_START |
| `smart_start_booking_created` | существующая система, если доступна | запись подтверждена | bookingId/атрибуция по согласованному контракту |

События игры не содержат вводимый текст, контакты, имя игрового «посетителя», медицинские сведения или детали бронирования. `bookingId` не попадает в доменный поток игры.

## Измерение пилота

- **Воронка:** увидели вход → открыли → начали → завершили S1 → S2 → разрешили помощь → S3 → нажали Smart Start → подтвердили запись.
- **Основная метрика для проверки гипотезы:** доля пользователей сегмента пилота с подтверждённой записью на Smart Start в течение 7 дней после первого показа карточки по сравнению с контрольной группой при одинаковых правилах доступности. Знаменатель — уникальные пользователи с показом, а не запуски сессий. Требуются экспериментальный флаг и связка с событием подтверждения записи.
- **Диагностика:** completion rate от уникальных стартовавших, отвал по станции, медиана и p90 попыток, доля повторных сессий, клики на Smart Start, 409/5xx, восстановление после сетевой ошибки.
- **Ограничение:** клик не равен записи; сравнение «игравших» и «не игравших» без рандомизации подвержено самоотбору. Если событие бронирования нельзя связать с экспозицией, основная бизнес-метрика не считается и остаётся только метрика перехода.

План пилота: согласовать сегмент новичков, единицу рандомизации по пользователю, срок наблюдения и минимальный объём до запуска. Не обещать изменение удержания или порядок в реальном зале по игровым событиям: эти эффекты потребуют отдельных наблюдений.
