# 04 · Evidence register

[Кейс](../../../README.md) / [Карта артефактов](../../../NAVIGATION.md) / [BA · Бизнес-анализ](../README.md) / **04 · Evidence Register**

Разделяем **факт**, **публичное утверждение**, **результат внешней проверки**, **предположение** и **неизвестное**. Публичные страницы не подтверждают поведение пользователей в приложении.

| ID | Тезис | Статус на 28.10.2026 | Доказательство / что проверить |
|---|---|---|---|
| EV-01 | В DDX действует Smart Start | Факт по официальному описанию | [Официальная страница](https://www.ddxfitness.ru/smart-start/) |
| EV-02 | Smart Start доступен на всех тарифах и через запись в приложении | Публичное заявление DDX | [Smart Start](https://www.ddxfitness.ru/smart-start/) и [FAQ](https://www.ddxfitness.ru/faq/) |
| EV-03 | Существует отдельная ознакомительная тренировка | Факт по официальной странице | [Описание услуги](https://www.ddxfitness.ru/group-training/3076/) |
| EV-04 | Новичок не видит приглашение к вводным занятиям в актуальном UX | Не установлено | Аудит действующей версии приложения, включая push/in-app/click-path |
| EV-05 | Значимая доля новых членов не знает об услугах | Не установлено | Интервью + когортная аналитика; размер и критерии «значимой доли» задаются до оценки |
| EV-06 | Конверсия в посещение ограничена недостатком осведомлённости | Гипотеза причинности | Сопоставить awareness, intent, доступность слотов, запись, посещение |
| EV-07 | Игровое действие усваивается лучше карточки | Гипотеза | A/B/C-тест и отдельная проверка понимания правил |
| EV-08 | Изменение поведения повлияет на churn/LTV | Долгосрочная гипотеза | Отдельное испытание с достаточным горизонтом; не выводить из `game_completed` |
| EV-09 | В DDX используется конкретный Game API, event broker или outbox | Неизвестно | Согласование с внутренней архитектурой; все названия в SA проектные |
| EV-10 | Настройка реальной скамьи безопасна по универсальному чек-листу | Недопустимое обобщение | В игре только правила обращения/обращения за помощью, без инструкций по конкретной модели |

## Минимальный план закрытия EV-04—EV-06

1. Зафиксировать версию приложения и платформу; пройти путь покупка → вход → подготовка к первому посещению → поиск занятия.
2. Провести короткие интервью с новыми клиентами: знают ли об услуге, понимают ли условия, пытались ли записаться, почему не посетили.
3. Получить по возможности обезличенные показатели показов, записей, слотов, отмен, фактических посещений по когортам. Отсутствие доступа к этим данным фиксировать, а не заменять предположениями.
