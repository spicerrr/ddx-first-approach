# 02 · Functional & system requirements

## Трассировка BA → SA

| BA | SA | Проверка |
|---|---|---|
| BR-01, BR-02 | SA-01 Необязательный доступ без тарифного paywall | Пропуск не ограничивает членство |
| BR-03, BR-04 | SA-02 Проверка четырёх станций с обратной связью | Корректный и некорректный ответ |
| BR-05 | SA-03 Сохранение и восстановление принятого сервером прогресса | GET после закрытия приложения |
| BR-06 | SA-04 Нет выдачи квалификации / допуска к оборудованию | Контентные и UX-проверки |
| BR-07, BR-08 | SA-05 Переход к штатной записи | Нет собственного POST booking |
| BR-09 | SA-06 Раздельные события игры, CTA, записи и посещения | Атрибуция без фиктивной брони |
| BR-10 | SA-07 Эксперимент и флаг | Пользователи контрольной группы не получают игровой вход |

## Инварианты
- Не более одной активной сессии на пользователя.
- Идентификатор владельца извлекается из доверенного контекста авторизации, а не передаётся клиентом.
- Версия сценария закрепляется при старте.
- Повтор операции с одинаковым Idempotency-Key не создаёт новый переход.
- Устаревшая revision → HTTP 409 с актуальным состоянием.
- Ошибочный ответ не меняет этап и объясняет ошибку.
- Игра не хранит оплату, историю InBody и содержимое действующей записи.
- Закрытие приложения не означает завершения сессии.
