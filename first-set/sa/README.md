## Граница решения

Предлагаемое место функции — «Точка старта» в DDX Fitness App. Браузерный прототип показывает этот путь и четыре игровые ситуации. Подготовка упражнения, запись к тренеру и управление доступом в клуб остаются в существующих контурах DDX.

| Компонент | Ответственность | Реализация в прототипе |
| --- | --- | --- |
| Управление сценарием | Вход, карта, открытие следующей станции, итоговый экран | [App](../demo/src/main.tsx), [экраны](../demo/src/ui/screens.tsx) |
| Игровой движок | Принимает локальные команды, проверяет правила и возвращает результат | [game.ts](../demo/src/engine/game.ts), [barbell.ts](../demo/src/engine/barbell.ts), [inventory.ts](../demo/src/engine/inventory.ts) |
| Движок подсказок | Состояние по учебному правилу, уровни H1–H4, реплика и демонстрация | [hints.ts](../demo/src/engine/hints.ts), [station-hints.ts](../demo/src/engine/station-hints.ts) |
| Загрузка ресурсов | Отдельные модули сцен, предварительная загрузка следующей, модель скамьи и резервное отображение | [station-board.tsx](../demo/src/ui/station-board.tsx), [station-resources.ts](../demo/src/ui/station-resources.ts), [bench-view.tsx](../demo/src/ui/bench-view.tsx) |
| Хранилище прогресса | Значение числа завершённых станций на текущем устройстве | [progress-storage.ts](../demo/src/engine/progress-storage.ts) |
| Обратная связь | Смена реплик, визуальный результат, короткий звук и вибрация при поддержке устройства | [coach-message.tsx](../demo/src/ui/coach-message.tsx), [feedback.ts](../demo/src/ui/feedback.ts) |
| Адаптер аналитики | Передаёт выбранные события интерфейса через локальный `CustomEvent` | [analytics.ts](../demo/src/engine/analytics.ts), [схема событий](contracts/events.schema.json) |

React, TypeScript, Three.js и Vite составляют стек веб-прототипа на GitHub Pages. Мобильную реализацию и выбор её стека определяет команда DDX после согласования границ интеграции.

## Состояние и переходы

| Состояние | Что хранится | Граница жизни |
| --- | --- | --- |
| Сценарий | Версия, порядок станций, предметы, места, правила итогов и генерации | Версия веб-сборки загружает [контракт 2.0](contracts/scenario-v2.sample.json) |
| Прохождение | Номер станции, фаза, размещения игрока, состав штанги и замков, положения скамьи. Для инвентаря отдельно `inventoryInitial` и `placements.INVENTORY` | Память открытого модуля. Возврат на карту сохраняет объект прохождения |
| Подсказки | Для правила `mistakeCount`, `hintLevel`, `hintRequested`, `demoOpened`, `resolved` | Память попытки. При смене станции состояние тренера сбрасывается |
| Сцена | Захваченный предмет, указатель, подсветка цели, анимации, положение камеры, способ ввода | Интерфейс. Содержимое попытки остаётся в игровом состоянии |
| Контрольная точка | Целое число завершённых станций в диапазоне от нуля до четырёх | Локальное хранилище браузера. При недоступности хранилища прохождение работает до закрытия страницы |

| Действие | Предусловие | Результат |
| --- | --- | --- |
| Открыть карточку | Пользователь находится в «Точке старта» | Карта показывает следующую готовую станцию. Сохранённое значение 4 открывает итоги |
| Войти на станцию | Станция готова к началу | `ready → playing`. У инвентаря один раз создаётся начальная раскладка |
| Вернуться с карты на станцию | Попытка активна | Тот же объект прохождения, та же раскладка и принятые размещения |
| Завершить одну из первых трёх станций | Выполнено условие станции | `playing → lesson`. Гантели и штанга показывают результат. Скамья остаётся доступна для свободной настройки. Переход через карту готовит следующую станцию |
| Убрать последний предмет инвентаря | Корректно размещены все оставшиеся предметы | `playing → complete`, записывается 4. После короткой анимации укладки открываются итоги. При уменьшенном движении переход происходит сразу |
| Подтвердить выход или перезагрузить | Есть начатый маршрут | Сохраняется число завершённых станций. Первая незавершённая начинается с новой попытки |
| Выбрать тренировку на итоговом экране | Маршрут завершён | Прямая ссылка открывает расписание выбранного формата DDX в новой вкладке. Игрок может вернуться на итоги и выбрать другой формат |
| Вернуться из итогов | Маршрут завершён | Кнопка ведёт в «Точку старта» и сбрасывает значение для повторного прохождения |

## Правила сценария

- **Гантели.** Шесть предметов имеют ссылки на парные места 8, 12 и 16 кг. Массу для реплик и маркировки движок получает из описания стойки. Станция завершается при заполнении всех трёх пар.
- **Штанга.** Гриф весит 20 кг. В наличии четыре диска по 5 кг, два по 10 кг, два по 20 кг и два замка. Проверка требует 80 кг в сумме, нулевую разницу сторон и два закрытых замка. Левая и правая стороны могут иметь разный набор дисков с равной суммой.
- **Скамья.** Последовательность частей и целевые позиции заданы в сценарии. В версии 2.0 это спинка в позиции 2 и сиденье в позиции 1. Фиксация оценивается при завершении жеста. Состояние камеры и временное положение в ходе жеста живут в 3D-сцене.
- **Инвентарь.** Сначала без возвращения выбираются два из пяти дисков. Затем выбираются три разные зоны хранения из четырёх и по одному предмету каждой выбранной зоны. Чистая функция принимает источник случайности, тесты передают предсказуемые последовательности. На полу остаются три диска и пять остальных предметов. Размещённые изначально предметы неподвижны. Остаток выводится из начальной раскладки и принятых действий игрока. Реплика категории появляется после размещения последнего оставшегося предмета этой категории.
- **Подсказки.** H0 задаёт задачу. H1 направляет внимание, H2 объясняет правило, H3 даёт конкретное направление, H4 предлагает показ приёма, если он предусмотрен. Для резинок, ковриков, блоков и роллов состояние ведётся по зонам. Для дисков инвентаря правило одно, конкретный штырь зависит от выбранного веса. Исправление сохраняет результат или следующий шаг в реплике.

## Производительность и отказоустойчивость

- `React.lazy` и `Suspense` загружают сцены по входу. Скамья и Three.js выделены в отдельную загрузку. На главной используются ресурсы оболочки. GLB, подробная графика станций и GIF-показы загружаются в игровом контексте.
- После входа на станцию планируется предварительная загрузка следующей. Её отказ обрабатывается локально. Изображения и запрос модели переиспользуются в памяти, статические файлы используют браузерный кэш размещения. Ошибочный запрос модели можно повторить.
- При сбое GLB или 3D-отрисовки доступна интерактивная схема. Граница ошибок станции предлагает выход в «Точку старта» с сохранением завершённых станций. Основным функциям мобильного приложения требуется независимый от модуля жизненный цикл.
- Уменьшенное движение выключает анимацию укладки и переходов. Для показа приёма используется статичный кадр. Звук выключается через помощь. Состояние и ошибки всегда отображаются интерфейсом.

## Аналитика и интеграции

[Схема](contracts/events.schema.json) фиксирует тип события, время, версию схемы и сценария. Для отдельных типов добавляются станция, правило, уровень подсказки или источник и формат выбранной тренировки.

| Событие | Момент |
| --- | --- |
| `first_approach_exposed` | В прототипе открыт экран «Точка старта» и отрисована карточка |
| `first_approach_started` | Пользователь запустил новую попытку на первой станции |
| `first_approach_stage_started` | Начата новая попытка на станции |
| `first_approach_stage_completed` | Условие станции впервые выполнено в попытке |
| `first_approach_hint_requested` | Запрошена подсказка |
| `first_approach_hint_level_reached` | Уровень данного правила повысился |
| `first_approach_demo_opened` | Открыт показ приёма |
| `first_approach_completed` | Завершена четвёртая станция |
| `first_approach_skipped` | Выход с карты подтверждён до запуска первой станции |
| `training_cta_clicked` | Нажата ссылка на расписание. `source=finish` для итогов, `source=club` для обычной навигации приложения. `training=smart-start` или `intro` определяет выбранный формат |

События доступны локальному потребителю в браузере. Приёмник DDX, параметры показа и переходы в штатные экраны приложения требуют отдельного согласования. Прототип открывает официальные страницы Smart Start и ознакомительной тренировки. Источники фактов бронирования и посещения — штатные системы DDX. Сопоставление с результатами пилота требует согласования целей, ключей и допустимого состава данных. Игровые команды обрабатываются на устройстве. Сетевое взаимодействие в демо сводится к загрузке статических ресурсов и переходу по ссылкам.

## Открытые вопросы для DDX

1. Кто и когда видит «Первый подход» в «Точке старта», можно ли открыть его повторно.
2. Насколько описанные стойки, скамьи и маркировки типичны для разных клубов. Кто подтверждает содержание при изменении оборудования.
3. Какой приёмник и какие фильтры событий используются, на каких условиях допустима связь с посещениями и бронированием.
4. Где находятся штатные экраны и поддерживаются ли переходы к занятиям и инструкциям из мобильного модуля.
5. Каковы исходные показатели первых визитов, профиль устройств, ограничения размера и время открытия основных экранов. Как определить пороги пилота.
