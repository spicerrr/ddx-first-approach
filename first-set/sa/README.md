# Системный анализ · «Первый подход»

**Спецификация потенциального игрового модуля для DDX Fitness App.** Не является описанием действующих микросервисов компании.

В спецификации разделены внешний продуктовый контур (членство, существующая запись, подтверждение посещений) и предлагаемый игровой домен (сессия, сценарий, действия, события). Экспериментальная пригодность идеи должна быть доказана до архитектурного решения о выделении сервиса.

| Артефакт | Содержимое |
|---|---|
| [System context](docs/01-context.md) | Cистемные границы и ответственность за переход к записи |
| [Requirements](docs/02-requirements.md) | BA → SA → AC, механики станций и инварианты |
| [State machine](docs/03-state-machine.md) | Session status vs stage/progress, конфликты и повторы |
| [Data model](docs/04-data-model.md) | Логические сущности, ключи, транзакционные гарантии |
| [Events](docs/05-events.md) | Источники истины, атрибуция, границы приватности |
| [Acceptance](docs/06-acceptance.md) | 24 позитивных/негативных приёмочных сценария |
| [Open questions](docs/07-open-questions.md) | Что необходимо узнать у DDX до интеграции |
| [OpenAPI](contracts/openapi.yaml) | Типизированные игровые действия, ошибки, ревизии и idem keys |
| [Event schema](contracts/events.schema.json) | Версионированный контракт игровых событий |

Браузерное [демо](../demo/README.md) реализует только локальный интерактивный сценарий и не подтверждает серверные гарантии. Реальный стек DDX, маршруты записи и инфраструктура аналитики неизвестны.
