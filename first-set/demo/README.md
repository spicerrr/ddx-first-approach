# «Первый подход» · интерактивный прототип

[Кейс](../../README.md) / [Карта артефактов](../../NAVIGATION.md) / [BA](../ba/README.md) / [SA](../sa/README.md) / **Интерактивное демо**


**Что демонстрирует:** четыре интерактивные станции, объяснение ошибочных действий, сохранение локального прогресса, отдельные полноэкранные состояния объяснения и финала, условный CTA существующих вводных услуг **без обязательного завершения игры**.

| Станция | Взаимодействие в браузере | Ограничение |
|---|---|---|
| Гантели | Выбор пары 8/12/16 кг и подходящей подписанной ячейки | Имитируется размещение, не реальный инвентарь |
| Штанга | Выбор виртуального диска 5/10 кг и левой/правой стороны; требуется 5+10 кг с каждой стороны | Вес учебный, не инструкция для тренировки |
| Скамья | Выбор шести безопасных проверок в логической последовательности | Нет механики конкретного фиксатора |
| Инвентарь | Сортировка восьми объектов по четырём зонам | Зоны условные; реальная схема клуба неизвестна |

## Локальный запуск

Из **корня** репозитория:

```bash
python3 -m http.server 8080
```

Откройте `http://localhost:8080/first-set/demo/`.

Для обнуления нажмите «Начать заново». Прогресс лежит в `localStorage` по ключу `first-approach-interactive-v2`. Браузерная модель не требует сервера, потому что все действия и сообщения моделируются в `logic.js`.

## Что НЕ реализовано

- Серверная авторизация, атомарное сохранение, идемпотентность, защита от гонок — только **предложены** в SA.
- Интеграция с приложением DDX, настоящие статусы записей, расписание и бронирование — отсутствуют.
- Локальные события — только демонстрационный журнал, не production analytics.
- Нативные экраны iOS/Android, реальные 3D-ассеты и подтверждённый бренд-гайд — отсутствуют.

Нельзя оценивать соответствие AC-10/11/20/22 (параллельные запросы, владелец, повтор) по этому клиентскому макету. Полный системный сценарий требует fake/API-реализации либо тестового backend.
