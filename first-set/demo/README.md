# Интерактивный прототип «Первый подход»

[В проект](../../README.md) · [Бизнес-анализ](../ba/README.md) · [Системный анализ](../sa/README.md)

Интерактивный макет мобильного сценария «Первый подход». На широком экране он отображается внутри рамки смартфона, на телефоне занимает экран устройства. Игрок открывает карту маршрута с главной, проходит четыре станции и может перейти к существующим вводным занятиям.

## Запуск

Используй Node.js 24. Из корня репозитория:

```bash
cd first-set/demo
npm ci
npm run dev
```

Открой адрес, который Vite напечатает в терминале (обычно `http://localhost:5173/`).

```bash
npm run build
npm run preview
```

Готовые файлы лежат в `dist/`. Адрес предварительного просмотра включает путь `/ddx-first-approach/`.

## Управление и сохранение

Выбери предмет и нажми на место хранения. Можно также перетаскивать предмет мышью или пальцем. С клавиатуры используй Tab и Enter или пробел. Неправильное действие сохраняет расстановку и объясняет, что изменить.

Штанга начинает с 60 кг. Слева и справа уже стоит по 20 кг, ещё 20 кг весит гриф. Добавляй диски 5 или 10 кг и проверяй результат вручную. Для зачёта нужны 80 кг и одинаковый набор с обеих сторон. Чтобы переставить диск, выбери его в лотке и укажи новую сторону. Для возврата в лоток нажми «Снять выбранный диск». Раскладка сохраняется даже между попытками.

На третьей станции перетаскивай выделенную деталь по стрелке. Сначала освободи фиксатор, затем подними подушку и ещё раз потяни её, чтобы проверить фиксацию. Спинка и сиденье регулируются по очереди. Перетаскивание вне выделенной детали вращает модель, щипок или колёсико меняет масштаб. Те же шаги доступны кнопками под подсказкой.

«Выйти» возвращает к главному экрану. «Продолжить» открывает незавершённую станцию или её пояснение. Для сброса используется «Начать заново» с подтверждением.

Состояние сохраняется в `localStorage` под ключом `first-approach-interactive-v3`. Проверяются версия сценария, допустимость действий, последовательность станций и журнал прохождения. Действительные сохранения формата v2 переносятся. При повреждённой записи интерфейс предлагает начать с чистого состояния; при запрете хранилища игра работает до закрытия страницы. Прогресс доступен на том же устройстве, в том же браузере и по тому же адресу.

Регулировка сохраняется после проверки фиксации соответствующей подушки. При выходе посередине незавершённое упражнение начинается с закрытого фиксатора. В сохранениях прежней версии пройденная станция остаётся завершённой.

## Код и графика

- [Правила](src/engine/game.ts) и [проверка сохранений](src/engine/store.ts) проверяются без браузера. Локальный сценарий 1.1 использует [состав станций версии 1.0](../sa/contracts/scenario-v1.sample.json), добавляет проверку раскладки штанги и самостоятельный выбор действий. Сохранения 1.0 переносятся при открытии игры.
- [Экраны](src/ui/screens.tsx), [размещение](src/ui/placements.tsx) и [станция скамьи](src/ui/bench.tsx) построены на React и TypeScript. [Просмотрщик](src/ui/bench-view.tsx) загружается при открытии станции и управляет четырьмя независимыми анимациями [модели GLB](public/art/bench.glb).
- Учебные углы 30° для спинки и 12° для сиденья, ход штифта и рычага заданы для упражнения. Скамья реконструирована по изображениям, точные положения упоров и кинематика реальной модели требуют отдельной проверки.
- [Изображения оборудования](public/art/) встроены в игру как отдельные WebP. Гантели, диски, скамья и инвентарь используют прозрачный фон. Для приветствия есть две версии изображения стойки.
- [Визуальные материалы](public/art/) опираются на прежние композиции стойки, грифа, скамьи и зон хранения. Оборудование переработано для актуального сценария и палитры. Пиксельное соответствие утверждённому комплекту мобильных макетов не проверялось.

Локальный журнал различает показ предложения, запуск, завершение станций и игры, переходы к занятиям. Аналитика не отправляется. Локальные события не предполагают получения подтверждений из систем DDX.

## Проверки

```bash
npm test
npm run build
npx playwright install --only-shell chromium
npm run test:e2e
```

Playwright открывает собранную версию по пути GitHub Pages. Он проходит игру через интерфейс, проверяет ошибки, возобновление и начало заново, клавиатуру, мышь, касание и сенсорное перетаскивание. Вёрстка проверяется на ширинах 320, 375, 390, 430, 768 и 1440 px. Снимки сохраняются в `test-results/`. При необходимости можно передать путь к системному Chromium через `PLAYWRIGHT_CHROMIUM_PATH`.

## GitHub Pages

Для первого запуска выбери [Settings → Pages](https://github.com/spicerrr/ddx-first-approach/settings/pages) → **Source: GitHub Actions**. [Рабочий процесс публикации](../../.github/workflows/deploy-pages.yml) работает из `main`, собирает приложение, проверяет его и публикует папку `dist/`. Браузерные снимки сохраняются в артефакте `browser-checks` соответствующего запуска.
