# Интерактивный прототип «Первый подход»

[В проект](../../README.md) · [Бизнес-анализ](../ba/README.md) · [Системный анализ](../sa/README.md)

Интерактивный макет мобильного сценария «Первый подход». Вход в игру расположен на главной DDX Fitness между карточками знакомства с клубом и календарём. За обложкой следуют знакомство с тренером и карта из четырёх дел. У игрока есть возможность пропустить игру и открыть Smart Start. На широком экране макет масштабируется целиком. Внутренний размер рамки iPhone 17 составляет 402 × 874 CSS-пикселя.

## Запуск

Используй Node.js 24. Из корня репозитория:

```bash
cd first-set/demo
npm ci
npm run dev
```

Открой адрес, который Vite напечатает в терминале (обычно `http://localhost:5173/`).

```bash
npm run build
npm run preview
```

Готовые файлы лежат в `dist/`. Адрес предварительного просмотра включает путь `/ddx-first-approach/`.

## Один маршрут

- **Гантели.** Определи свободные места по маркировке соседних пар. На верхней полке веса 2, 4, 6 и 8 кг, на нижней — 10, 12, 14 и 16 кг. Вес растёт слева направо, места для пары идут подряд.
- **Штанга.** Пустой гриф весит 20 кг. Собери 80 кг с одинаковыми дисками с обеих сторон, затем поставь и защёлкни оба замка. Например, с каждой стороны можно поставить по диску 20 и 10 кг. При ранней попытке поставить замок он возвращается в лоток, и тренер объясняет порядок.
- **Скамья.** Посетитель просит выставить спинку на 20°, сиденье на 4°. Каждый шаг начинается с короткого показа. Удерживай фиксатор одним пальцем, другим совмещай подушку с контуром целевого положения. Угол засчитывается после отпускания фиксатора. После обеих настроек открывается свободный режим и кнопка «Следующая станция».
- **Инвентарь.** Перетащи восемь предметов с пола на обозначенные места хранения.

Возьми диск на штанге или в лотке. При установке диск скользит от края втулки к собранному набору. На установленном замке нажми рычажок, чтобы защёлкнуть его. Перед снятием сначала открой замок.

При посадке тяжёлого диска устройство посылает два импульса, при посадке 10 кг — короткий, а у 5 кг остаётся визуальная посадка. Вибрацию воспроизводят браузеры с поддержкой [Vibration API](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate). В Safari на iPhone срабатывает анимация посадки.

Клавиатура поднимает предмет пробелом или Enter. Клавиша Tab переводит фокус к месту назначения. Пробел или Enter завершает перемещение, Escape отменяет выбор. На скамье удерживай пробел и меняй угол стрелками либо перетаскивай подушку мышью.

Переходы к маршруту и информации о занятиях сохраняют текущее состояние в открытом прохождении. Выход на главную, закрытие или перезагрузка страницы начинают чистое прохождение.

## Код и графика

- [Правила](src/engine/game.ts) и [сборка штанги](src/engine/barbell.ts) работают в памяти. Макет использует порядок станций из [контракта 1.0](../sa/contracts/scenario-v1.sample.json). События прохождения остаются в памяти и очищаются вместе с игровым состоянием.
- [Экраны](src/ui/screens.tsx) и [игровые сцены](src/ui/gym.tsx) построены на React и TypeScript. В [наборе графики](public/art/) лежат растровые изображения стойки, гантелей с маркировкой, грифа, дисков и замков. При перетаскивании подсветка показывает область под удерживаемым предметом.
- [Станция скамьи](src/ui/bench.tsx) управляет четырьмя анимациями [учебной модели GLB](public/art/bench.glb). Целевые углы относятся к игровому заданию.

## Проверки

```bash
npm test
npm run build
npx playwright install --only-shell chromium
npm run test:e2e
```

Playwright открывает собранную версию по пути GitHub Pages. Он проходит игру через интерфейс, проверяет пары на стойке, защёлки замков, настройку скамьи двумя указателями и ручной переход в следующий зал. Покрыты клавиатура, мышь и сенсорные жесты. Вёрстка проверяется на ширинах 320, 375, 402, 430, 768 и 1440 px. Снимки сохраняются в `test-results/`. При необходимости можно передать путь к системному Chromium через `PLAYWRIGHT_CHROMIUM_PATH`.

## GitHub Pages

Для первого запуска выбери [Settings → Pages](https://github.com/spicerrr/ddx-first-approach/settings/pages) → **Source: GitHub Actions**. [Рабочий процесс публикации](../../.github/workflows/deploy-pages.yml) работает из `main`, собирает приложение, проверяет его и публикует папку `dist/`. Браузерные снимки сохраняются в артефакте `browser-checks` соответствующего запуска.
